# ai-engineering-workflow skills (v1.5 — Epic/Sprint Planning + 4-Station Jira-Centered Small-Team Workflow)

Eight Jira-centered engineering workflow skills — plus a dynamic multi-agent orchestration system skill — designed for small and growing teams where one person may hold multiple roles, one role may be shared by multiple members (`1-to-N` role pools), and **Jira** serves as the single permanent planning and per-feature lifecycle asset.

## Planning + 4-Station Workflow Skills (`skills/team-*`)

| Station | Skill | Modes | Purpose |
|---|---|---|---|
| **Init** | `skills/team-init/` | `init` / `auth` | Interactive inquiry-first setup of `.ai-workflow/team-config.json` (including `commit_policy`, `commit_message_pattern`, `qa_handoff_mode`, `status_mapping.dev_done`, and `epic_link_field`), `.ai-workflow/bin/jira_sync.py`, and `docs/shared/engineering-standards.md`. Supports **progressive role claiming** (`claimed_roles` / `unclaimed_roles`), **1-to-N multi-member role pools** (`specialty` tags), and non-destructive collaborator **`auth`** onboarding (all Jira/Qase tokens stored exclusively in gitignored `.ai-workflow/credentials.json` with `0600` permissions). |
| **Planning** | `skills/team-plan/` | `epic` / `decompose` / `sprint` / `commit` / `status` | Plans Epic context, platform-neutral Epic-to-Story decomposition (`epic-decompose` with mandatory `dry_run: true` preview and topological wave creation), and Future/Active Sprint membership with preview-before-apply safeguards. Keeps Epic as the cross-Sprint container and routes selected Stories/Tasks/Bugs into the existing delivery workflow without coupling `run-workflow` or multi-Story sub-agents into core `team-*`. |
| **Router** | `skills/team-next-step/` | — | Read-only single-command entry (`$team-next-step`) inspecting `team-config.json`, `.ai-workflow/active/<JIRA-KEY>.json`, Epic progress (`status --epic <EPIC-KEY>`), and live Jira state (auto-discovering active Stories & standalone Bugs via JQL, reconciling Jira Web UI edits, and surfacing `awaiting_qa_deploy` or `triage_closed` states) to recommend the exact next station, mode, and owner. |
| **Station 1** | `skills/team-spec/` | `one-pass` / `draft` / `backfill` | Scale-aware unified specification & design: small/clear stories finish in one pass (**"抓大放小"**, ≤ 3 material questions); complex/ambiguous stories iterate via multi-round `draft` deep-dives + 6-Dimension AC Completeness Checklist; existing Stories support **`--backfill`** / `--preserve-owner` with optional `Risks & Open Questions` (`--risks`, `--open-questions-json`) and 5-category evidence discipline without altering owner, assignee, status, or lifecycle state. Supports incremental AC upsert, Jira description drift guard, strict `has_data` scoping (schema/migration/storage-format/data-model changes only), and conditional UI (`has_ui`) / API (`has_api`) specs synced to Jira via inline-Markdown ADF. |
| **Station 2** | `skills/team-dev/` | `plan` / `implement` | Decomposes approved specs into verifiable slices (`TASK-001..N` → Jira `Sub-task` with rich structured Implementation Steps/Target Files/Verification and specialty-matched developer auto-assignment) or runs **Dev Fast-Track** (guarded to `<= 3` ACs & `low`/`medium` risk). Implements code & tests in strict priority (`BUG-*` > `TASK-###` > `REV-###`), composes specialist craft skills (Bring-Your-Own-Skill hook), enforces a 5-check review-aligned exit gate (including `docs/shared/engineering-standards.md` §4 / `AGENTS.md` Commit Format & dual Jira keys `<STORY-KEY>` + `<SUBTASK-KEY>`), pauses at the Human-in-the-Loop Commit Gate (`commit_policy`: `"confirm_before_commit"` default vs `"auto_on_test_pass"`), and checks off completion via `complete-task` (with `--root-cause` / `--solution` backfill on bug fixes and non-blocking `commit_message_warnings` / `bug_fix_warnings`). |
| **Station 3a** | `skills/team-review/` | — | Combined Dev Handoff & 3-axis Code Review against ACs, design, `docs/shared/engineering-standards.md` (fallback: `AGENTS.md`), and Commit/dual-Jira-key compliance. Automatically routes to a peer reviewer in `roles.reviewer.members` when available (or records transparent AI self-review in solo teams), supports both `"immediate"` and `"gated_by_deploy"` (`dev_done` -> `promote-qa` / CI/CD `in_qa`) QA handoff modes, and enforces strict HITL confirmation & cross-person SoD Clean Stop. |
| **Station 3b** | `skills/team-qa/` | `plan` / `verify` / `report` / `triage` | Parallel **3-tier QA** (`automated` / `external` / `manual` with anti-false-pass guardrails & `qa_identity_guardrail`) across a remembered **`jira-comment`** or **`qase`** (Qase TestOps API v1) backend. **`plan`** runs in parallel even during `awaiting_qa_deploy`; **`verify`** (deploy-gated under `gated_by_deploy`) ingests JUnit XML/JSON/manual results and files linked Jira `Bug` tickets + media attachments (`--attach`) synced to Jira & Qase Runs/Defects; **`report`** handles unscripted exploratory Story bugs (`TC-EXP-###`) and standalone production/CS `Bug` intake (`--standalone` / `--adopt`); **`triage`** (`triage-bug`) handles human-authorized non-code-fix Bug closure (`Not a Bug`, `Won't Fix`, `Duplicate`, `Cannot Reproduce`) or `Fixed` reopen with auditable `waived` / `not-applicable` TC dispositions. |
| **Station 4** | `skills/team-release/` | — | Reconciles live Jira state, verifies all 5 release gates (including parity-checked audited `waived` / `not-applicable` TC waivers and zero open Bugs) on the candidate commit, runs **scale-aware Living HTML Manual sync** under `docs/manuals/<manual-name>/<manual-name>.html`, posts the Release Summary (with **Bug Triage & Risk Acceptance Disclosure** when applicable), propagates `resolved_depends_on_keys` to sibling Epic Stories, transitions the Jira Story (or standalone Bug) to `Done`, and deletes `.ai-workflow/active/<JIRA-KEY>.json`. |

## Core Workflow Capabilities

- **Zero-CLI Single-Entry UX, Inline ADF & `zh-TW` Default Prose:** Humans interact in plain natural language or invoke `$team-next-step` at any point; AI executes `.ai-workflow/bin/jira_sync.py` in the background, converts inline Markdown (bold, italic, inline code, links, strikethrough, nested formatting) to valid Jira ADF, and writes human-facing specs, reviews, QA tables, and release notes in **Traditional Chinese (繁體中文)** by default.
- **Platform-Neutral Epic/Sprint Planning Layer:** `$team-plan` previews Epic context, decomposes an existing Epic into wave-ordered child Stories via `epic-decompose` (`dry_run: true` preview -> explicit confirmation -> `--apply`, with `parent` -> `epic_link_field` fallback), tracks cross-Story progress via `status --epic <EPIC-KEY>`, and manages Future/Active Sprint membership. Sprint membership does not replace Story delivery gates, and Phase 1 stays strictly platform-neutral across all clients.
- **Cross-Machine Hydration & Bidirectional Jira Web UI Reconciliation:** Syncs structured state via hidden Jira Issue Property (`ai_workflow_state`) and automatically reconciles manual Jira Web UI changes (Sub-tasks added/reopened, linked Bugs, Assignee updates, CI/CD `in_qa` transitions, and Story Description edits) before station actions.
- **1-to-N Role Pools, Strict HITL Gates & SoD Clean Stop:** Supports both multi-role individuals (`same_person: true` suppresses self-`@mention` noise via `auto-consolidated` only and **never** auto-chains — always pausing for explicit confirmation with `can_auto_chain_next_station: false`) and multi-member teams (automatic Story/Sub-task/Bug assignee resolution, specialty matching, peer-review selection, `qa_identity_guardrail`, `Stop & Yield on Fix`, and cross-person Separation of Duties Clean Stop).
- **Configurable Commit & Deploy Governance (`team-config.json`):**
  - `commit_policy`: `"confirm_before_commit"` (default — stops after local tests pass before `git commit` & `complete-task`) or `"auto_on_test_pass"` (opt-in); optional `commit_message_pattern` regex for non-blocking format reminders.
  - `qa_handoff_mode`: `"immediate"` (default) or `"gated_by_deploy"` with `status_mapping.dev_done` and `promote-qa` to decouple Dev completion from multi-environment QA deployment.
  - `epic_link_field`: optional custom Jira Epic Link field ID fallback for `epic-decompose` when `fields.parent` is rejected.
- **Lightweight Standalone Production Bug Track & Bug Triage:** Standalone or adopted CS/production `Bug` tickets registered via `$team-qa` (`report --standalone`) bypass `team-spec` and Sub-task ceremony, flowing directly through `team-dev -> team-review -> team-qa (verify) -> team-release` (or closing cleanly via human-authorized `$team-qa` `triage` / `triage-bug` when no code fix is warranted).

## First-Principles Asset Boundary

- **Per-Feature Lifecycle Assets (Jira + Gitignored Local Scaffolding):**
  - User Stories, ACs, Sub-tasks, Code Review summaries, QA Test Plans & Verification tables, Bug tickets, and media evidence live permanently in **Jira** (and optionally **Qase TestOps**).
  - `.ai-workflow/active/<JIRA-KEY>.json` (gitignored) stores active machine-readable state and is automatically deleted on release (`jira_sync.py close-story`). `.ai-workflow/credentials.json` (`0600`, gitignored) stores personal/per-role Jira and Qase API tokens. No per-feature process markdown files (`docs/requirements/`, `docs/design/`, `docs/qa/`, `docs/release/`, `analysis.md`, etc.) are ever committed to Git.
- **System-Wide Living Assets (Committed to Git):**
  - `.ai-workflow/team-config.json` and `.ai-workflow/bin/jira_sync.py` (shared team/status mapping and stdlib-only CLI wrapper).
  - `AGENTS.md` and `docs/shared/engineering-standards.md` (canonical engineering, security, testing, and Git Commit/PR rules).
  - Optional `docs/shared/glossary.md`, `docs/shared/adr/ADR-<NNN>-<slug>.md`, and portable dark-sidebar product/API manuals under `docs/manuals/<manual-name>/<manual-name>.html` (`./screenshots/`, `./diagrams/`).
